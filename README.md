# NPC 시청각 기반 플레이어 추적

플레이어를 추격하는 NPC가 플레이어 좌표를 그대로 읽는 방식으로 추격하면, 사람이 추격하는 것과는 거리가 멀고
플레이어의 긴장감이 떨어집니다.

따라서 NPC가 **보이는 것과 들리는 것만으로** 플레이어 위치를 추정해 추격하도록 만들고,
그 이동 조건이 실제로 타당한지 5개 환경에서 500회로 측정해보았습니다.

## 개발 정보

- **기간** 2026.03 – 2026.06
- **분류** 학부 졸업연구 (1인 개발 — 클라이언트 + 추론 서버)
- **환경** Unity · C# · Python · FastAPI · PyTorch · YOLOv8 · EZ-VSL

## NPC 판단 기준

**1. 이미지 추출**
NPC 카메라가 보는 화면을 RenderTexture로 받아 256×256 JPG로 인코딩합니다.

**2. 오디오 추출**
반경 45m 안에서 재생 중인 `AudioSource`를 골라
거리에 따라 감쇠한 뒤 더해 1초 분량의 WAV로 만듭니다.

**3. 서버로 전송**
추출한 이미지와 오디오를 서버로 보냅니다. 
EZ-VSL이 이미지와 오디오를 받아 소리가 난 위치를 224×224 히트맵으로 변환하고,
정확도를 높이기 위해 YOLOv8로 사람을 검출합니다. 
이 두 결과의 좌표 거리를 재서 같은 지점인지 확인한 뒤 후보를 돌려줍니다.

**4. 추격**
히트맵 좌표를 FOV와 aspect로 방향 벡터로 바꾸고, Raycast로 추격 위치를 정합니다.
캡처 당시 포즈를 기준으로 변환하여 이동합니다.

```mermaid
graph LR
  A[화면 캡처] --> B[소리 합성]
  B --> C[추론 서버]
  C -->|후보 좌표| D[방향 역변환]
  D --> E[NavMesh 보정]
  E --> F[FSM 전이]
```

## NPC 상태

`Scan` · `LocalScan` · `FullScanAtSpot` · `FaceDirection` · `Move` · `Chase` · `Return` · `FaceReturn` · `Idle`

처음에는 360도로 이동합니다. 이동 직후에는 NPC 위치를 기준으로 양쪽 90도,
그래도 찾기 못하면 두 바퀴 회전하며 추격 대상을 찾습니다.
회전 중에도 매 프레임 조건을 확인합니다.

## 실험

시야가 트인 정도가 다른 5개 환경을 만들고, 사람 검출(YOLOv8) 사용 여부만 바꾸어 각각 50회씩 총 500회를 측정했습니다.
시행 결과는 클라이언트가 서버로 전송하여 표로 자동 집계됩니다.

| 환경 | 검출 미사용 | 검출 사용 |
|---|---|---|
| 개방평지 | 96% | 94% |
| 동물혼재 | 86% | 82% |
| 자연지형 | 76% | 76% |
| 도심건물 | 66% | **42%** |
| 실내복도 | 92% | **8%** |

시야가 트인 환경에서는 성공률을 유지하면서 이동 횟수가 30~50% 줄었지만,
시야가 막힌 환경에서는 성공률이 크게 떨어졌습니다.
따라서 시야가 많이 가려지고, 대상이 많이 가려지는 환경의 경우 YOLO를 사용하지 않고,
시야가 트인 환경에서는 YOLO를 사용하는 방식으로 나누어 사용하는 것이 좋습니다.
